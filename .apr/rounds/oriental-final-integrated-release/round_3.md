2. **Admin login regresses into a pre-hydration secret leak.**  
   The login API now intentionally requires same-origin JSON, but `AdminLoginForm` removes the prior `method="post"` / `action="/api/admin/login"` safe fallback and leaves a bare `<form ... onSubmit=...>`. If hydration is delayed, JS fails, or a submit fires before React binds the handler, the browser default is a GET submission to the current URL, risking `ADMIN_REVIEW_TOKEN` in URL/history/server logs/referrers. The removed comment explicitly documented why `method="post"` was there. See `.apr/evidence/oriental-final-implementation.patch:650-656` and `.apr/evidence/oriental-final-implementation.patch:1718-1726`. This violates the principal-bound admin/secret boundary required by `.apr/specs/oriental-final-integrated-release.md:65-68`.

3. **Privacy deletion can report `ok: true` before erasure is complete.**  
   Convex deletion intentionally sets `complete = false` when bounded privacy deletion limits are saturated, e.g. too many matching voice sessions/leads/related rows, but the HTTP route still returns status 200 with `{ ok: true, ..., complete: false }` and logs a “completed” event name. That is not a safe machine-checkable success contract for subject erasure. The spec requires verified deletion to remove matching leads/events/linked or email-matching voice sessions and addressable downstream copies before reporting success. See `.apr/evidence/oriental-final-implementation.patch:3935-3950`, `.apr/evidence/oriental-final-implementation.patch:3972-3994`, `.apr/evidence/oriental-final-implementation.patch:733-755`, and `.apr/specs/oriental-final-integrated-release.md:91-99`.
