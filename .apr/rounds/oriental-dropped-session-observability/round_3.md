## Blocking finding

**BLOCKER — the deadline supervisor loses control of its detached child during release cancellation.**

`scripts/run-command-with-deadline.ts:24-29` deliberately starts the command in a separate process group. The only group-termination path is the deadline callback at `scripts/run-command-with-deadline.ts:32-45`. The remaining handlers at `scripts/run-command-with-deadline.ts:47-65` cover only child `error` and `exit`; there is no cleanup for `SIGINT`, `SIGTERM`, `SIGHUP`, or an early supervisor exit.

That creates this concrete failure sequence:

1. The lifecycle migration or orphan verifier is running as the detached child group.
2. An operator presses Ctrl-C, the release shell is terminated, or CI sends a cancellation signal to the foreground release group.
3. The supervisor exits under its default signal handling.
4. The detached child does not receive that foreground-group signal.
5. The supervisor’s 10-minute or 15-second timer disappears with the supervisor.
6. The child continues without the advertised total-process deadline.

For the lifecycle command, this means `scripts/backfill-voice-session-lifecycle.ts` can continue performing Convex mutations after the release operation was deliberately cancelled. For the verifier, a non-resolving Convex request can survive beyond the advertised 15-second total bound. The children are therefore bounded only while their supervisor remains alive, which does not satisfy the finite process-lifetime and process-group cleanup contract.

The test does not catch this. `tests/release-command-deadline.test.ts:17-47` makes the **direct child itself** write the delayed marker. Killing only that direct child through the fallback `child.kill("SIGKILL")` would pass exactly the same test; no grandchild proves that the negative-PID process-group kill occurred, and no cancellation test terminates the supervisor before its timer.

The correction must:

* centralize idempotent process-group termination;
* invoke it for the deadline and for at least `SIGINT`, `SIGTERM`, and `SIGHUP`;
* preserve a nonzero cancellation exit after the child group has died;
* prevent PID-reuse cleanup after a normal child exit;
* add a timeout test where a **grandchild** performs the delayed mutation;
* add a cancellation test that signals the supervisor group and proves the detached descendant cannot mutate afterward.

Until then, the claimed process-group and total-child-process proof is false-green.
