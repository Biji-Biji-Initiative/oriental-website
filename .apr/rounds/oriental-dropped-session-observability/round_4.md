## Release blocker

### BLOCKER — the deadline supervisor still has a cancellation race and does not establish process-group completion

`scripts/run-command-with-deadline.ts` starts the detached command before it installs any cancellation or exit cleanup:

* the detached child is spawned at patch lines 688–693;
* `SIGINT`/`SIGTERM`/`SIGHUP` handlers are installed only at lines 713–728;
* abnormal-exit cleanup is installed only at lines 730–731.

A signal arriving after `spawn()` has created the detached process but before those handlers are armed takes Node’s default termination path. The supervisor dies without calling `terminateChildGroup()`, while the newly detached child group is outside the supervisor’s terminal process group and can continue running. For `convex:backfill:voice-session-lifecycle`, that surviving process can perform lifecycle mutations after cancellation. This is exactly the delayed-mutation failure the supervisor is intended to prevent.

There is a second completion hole in the same file. `finish()` treats exit of the immediate child as completion of the entire command group, clears the deadline, removes abnormal-exit cleanup, and can return status zero without checking whether the process group still contains descendants (`scripts/run-command-with-deadline.ts`, patch lines 741–769). A direct child can spawn and unref a same-group grandchild, exit zero, and leave that grandchild running after the supervisor reports success. That can turn the verifier into a false-green release gate if an intermediate wrapper ever exits before its verifier descendant, and it directly contradicts the evidence claim that cancellation is held until the detached group dies.

The new tests do not cover either path:

* their helper’s direct child deliberately remains alive forever using `setInterval()` (`tests/release-command-deadline.test.ts`, patch lines 1125–1128);
* the cancellation test waits until the child has written its readiness file before sending `SIGTERM` (lines 1243–1246), guaranteeing that cancellation occurs long after handler installation;
* no test has the process-group leader exit while its grandchild remains;
* no test exercises cancellation during the spawn-to-handler-registration window.

The remediation is to arm signal and abnormal-exit handling before spawning, using a nullable child/PGID plus a pending-cancellation state. Once spawned, any already-received cancellation must immediately terminate the group. The supervisor must also distinguish “leader exited” from “group is gone”: on every direct-child exit, probe the process group, kill surviving members, wait within a bounded kill-settle interval for `kill(-pgid, 0)` to report that the group no longer exists, and reject a nominally successful child exit if descendants survived it. Add hostile tests where:

1. the child immediately causes `SIGHUP`, `SIGINT`, and `SIGTERM` during startup and a grandchild attempts a delayed marker write; and
2. the child spawns a same-group grandchild and exits zero immediately.

Both cases must end nonzero with no delayed marker.
